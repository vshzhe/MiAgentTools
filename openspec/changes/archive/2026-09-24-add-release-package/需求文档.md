## 一、原始需求

将用户全局目录下的 `auto-package-verifier` 打包质量校验技能迁移到 VenusAgentTools 项目，纳入 venus 技能体系：

1. **迁移技能**：把 `C:\Users\venus\.claude\skills\auto-package-verifier` 迁移为本项目 venus 技能（名 `venus_release_package`），使其可经 `venus init` 分发、纳入版本管理与一致性测试保障。
2. **校验脚本随 SKILL 生成**：检查自动打包技能的关联校验脚本（pre-package-check.sh、verify-package.sh）一并迁移，随 SKILL 或初始化时一起生成，消除脚本游离漂移。
3. **打包脚本本体备份到项目内**：把外部 `E:\github\Auto-Package-Svn` 的打包脚本本体（auto-package.sh + conf + ps1 + lib/ecj jar）备份到本项目 `vendor/auto-package-svn/`，技能使用项目内脚本；运行时路径可配置，用户可按需指定路径。
4. **增强升级信息归集**：迁移版本的技能需根据"打包文件 + 提案"，自动查找对应的 SQL、配置参数信息，输出到对应文档中，用于升级使用——补齐"打包→校验→升级文档"交付闭环。

**背景问题**（来自 proposal.md Why）：原技能不可经 venus init 分发、校验脚本独立存放易漂移、打包脚本本体外部依赖不可版本控制/不可移植、三阶段校验收步于"产出文件正确"未归集升级所需 SQL/配置信息。

## 二、需求分析

### 需求理解

将一个基于 SVN 增量打包（auto-package.sh）的打包质量校验技能纳入 venus 技能体系，打包脚本本体备份到项目内 vendor 且路径可配置，并扩展第四阶段"升级信息归集"，使增量包交付同时附带升级所需的 SQL 与配置参数清单。技能以 SVN 变更清单为校验基准，适用 Venus4A 系列 Web 项目与 AccountManager/AuthServer 等 Server 项目。

#### 场景一: 技能分发与安装（管理配置场景）

把打包校验技能纳入 venus 技能生命周期管理，校验脚本与参考文档随技能一并生成分发。

需要实现的功能点：
- **技能模板创建**：新建 tr_release 类型技能模板，迁移源技能三阶段校验指令（逐段复制，不改行为）
- **校验脚本与参考文件嵌入**：两个校验脚本 + 两个参考文档作为 references 嵌入模板，随 build/init 生成到技能目录
- **注册与安装**：注册到技能注册表，经 workflows 勾选安装（不入默认集，可选扩展件）
- **dogfood 安装**：本项目 .venus/config.yaml workflows 勾选新技能，venus init 安装到 .claude/skills/

#### 场景二: 打包运行时备份与路径可配置（管理配置场景）

把外部打包脚本本体备份到项目内 vendor，技能通过可配置路径调用，不绑定具体位置。

需要实现的功能点：
- **运行时备份**：把 auto-package.sh + conf + ps1 + lib/ecj jar + 使用说明备份到 vendor/auto-package-svn/，保持自包含目录结构
- **路径可配置**：技能读 .venus/config.yaml 的 auto_package.runtime_dir 解析运行时目录，默认 vendor/auto-package-svn
- **灵活指向**：用户可配置指向其他路径（外部 E:\github 或目标项目自己的 vendor）
- **路径校验**：解析路径无 auto-package.sh 时报错提示

#### 场景三: 打包三阶段质量校验（业务使用场景）

在 SVN 增量打包前后提供质量闸门，拦截参数/环境/编译/一致性错误。

需要实现的功能点：
- **阶段一打包前预检**：拦截必填参数缺失、版本号格式/超 HEAD、路径/工具链/配置问题，FAIL 时不进入打包
- **阶段二打包执行监控**：通过可配置运行时路径调 auto-package.sh 监控输出，编译/SVN 失败时暂停报告
- **阶段三打包后一致性校验**：以 SVN 变更清单为基准核对产出，检测缺失/编译缺失/内部类缺失/应删未删/多余文件
- **参数传递与追问**：从自然语言提取 4 个必需参数，缺失主动追问，版本号绝不猜测

#### 场景四: 升级信息归集（AI/智能场景）

阶段三校验通过后，AI 语义归集本次增量包的升级信息，输出升级文档供运维升级部署。

需要实现的功能点：
- **提案反查**：读产出 readme.txt 提交说明提取 change 名，定位 OpenSpec 变更提案；反查失败静默降级
- **SQL 四源归集**：从产出 .sql 文件、Java/Mapper XML 内嵌、db/migration 目录、提案 tasks [DB脚本] 标记归集待执行 SQL
- **配置三源归集**：从产出配置文件、提案声明配置项、特定配置文件归集待变更配置参数
- **多版本去重分组**：多版本打包按 change 名去重分组，升级文档含多 change 区段
- **升级文档输出**：输出升级文档.md 到产出目录，随增量包交付运维

### 非本期范围

| 范围项 | 说明 | 原因 |
|--------|------|------|
| 新增 SKILL_TYPES 类型 | 不新增 tr_package 类型（9→10） | tr_release 已足以承载打包校验+升级文档，能不扩则不扩 |
| 入默认 workflow 集 | 不加入 DEFAULT_WORKFLOWS | 打包校验是 Venus4A 专项，非通用，经 workflows 勾选安装 |
| 修改 auto-package.sh 本体逻辑 | 仅备份到 vendor，不改脚本内容 | 保持自包含结构，迁移不引入行为漂移 |
| 扩展 venus init 部署二进制资产 | 不改 init/CLI 支持二进制部署 | 运行时路径可配置已解决部署语义，用户按需配置 runtime_dir |
| 阶段四脚本化 | 不将升级归集写为 .sh 脚本 | 提案关联与 SQL/配置归集需 AI 语义判断，作为 instructions 指导 AI 执行 |
| 单独迁移源使用说明.md | 不作为独立文件迁移 | 内容与 SKILL.md 高度重叠，独有内容并入 instructions |
| 改 DEPS 依赖注入表 | 不新增依赖注入规则 | 本技能不编排其他技能，无注入关系 |

// 来源: design.md D15 — 运行时路径解析逻辑
FUNCTION 解析运行时目录()
    runtime_dir = 读取配置(".venus/config.yaml", "auto_package.runtime_dir")
    IF runtime_dir 为空 THEN
        runtime_dir = "vendor/auto-package-svn"

    END IF
    返回 runtime_dir

## 三、技术框架

### 3.1 总体技术框架

```
┌─────────────────────────────────────────────────────┐
│ src/core/templates/workflows/                       │
│ release-package.ts                               │
│  ├ instructions（三阶段迁移 + 阶段四新增）          │
│  │  └ 阶段二调 <runtime_dir>/auto-package.sh        │
│  └ references[]：校验脚本 + 参考文档                │
└──────────────────────┬──────────────────────────────┘
                       ▼ 注册
┌─────────────────────────────────────────────────────┐
│ registry.ts WORKFLOW_PAIRS（tr_release 分区）       │
└──────────────────────┬──────────────────────────────┘
            ┌──────────┴──────────┐
            ▼                     ▼
   pnpm generate:skills        venus init
            │                     │
            ▼                     ▼
   skills/ 快照              .claude/skills/ 安装产物
   (SKILL.md+校验脚本+       (同左 + commands/)
    参考文档)

┌─────────────────────────────────────────────────────┐
│ vendor/auto-package-svn/（项目内备份，独立于技能）  │
│  ├ auto-package.sh + auto-package.conf + ps1        │
│  └ lib/ecj-4.6.3.jar（2.4MB 二进制，git-tracked）   │
│  自包含：SCRIPT_DIR 定位同目录 conf 与 lib/ecj jar  │
└──────────────────────┬──────────────────────────────┘
                       ▼ .venus/config.yaml
                  auto_package.runtime_dir
                  （默认 vendor/auto-package-svn，可配置）
```

技能体系数据流：TS 模板（含校验脚本 references 嵌入）→ registry 注册 → generate:skills/init 分发。打包运行时独立于技能存在于 vendor/，技能阶段二读 .venus/config.yaml 的 runtime_dir 解析路径调用，二进制 jar 不走 references（utf8 不支持）。

### 3.2 关键技术决策

| 决策点 | 选择方案 | 原因 |
|--------|----------|------|
| 类型与命名 | tr_release / venus_release_package | 打包校验+升级文档属发布交付，与 venus_tr_release_version 互补，不扩类型体系 |
| 校验脚本嵌入 | references 嵌入（path: scripts/*.sh），随 build/init 生成 | writeSkillReferences content 无关，校验脚本不引用外部路径可原样嵌入 |
| 打包脚本本体 | 备份到 vendor/auto-package-svn/（真实文件，含二进制 jar） | jar 不能 utf8 嵌入，skills/ 被清空；vendor 稳定可 git-track；auto-package.sh 自包含 |
| 运行时路径 | 可配置（.venus/config.yaml auto_package.runtime_dir，默认 vendor） | 解耦技能与运行时位置，用户可指向其他路径，无需 CLI 改动 |
| 默认集 | 不入 DEFAULT_WORKFLOWS，经 workflows 勾选 | 打包校验是 Venus4A 专项，非通用 |
| 迁移方式 | 逐段复制 + 定点替换 | 禁重写正文防漂移；阶段二路径定点替换为可配置 |
| 阶段四形态 | 同技能内阶段四 | 打包→校验→升级文档管线内聚 |
| 提案关联 | 读 readme.txt 提取 change 名反查 | 复用 auto-package.sh 已生成 readme.txt |
| 反查失败 | 静默跳过提案来源，仅归集产出文件 | 升级文档始终可基于产出文件生成，不阻断 |
| 多版本组织 | 按 change 名去重分组 | 适应各种提交粒度 |

### 3.3 接口设计

本变更不涉及（无 API 端点设计；技能通过 bash 调用脚本 + AI 执行 instructions，无对外接口契约）。

### 流程说明

| 步骤 | 操作说明 | 异常处理 |
|------|----------|----------|
| 阶段一 | 跑 pre-package-check.sh 校验参数/路径/配置/工具链/版本号≤HEAD | FAIL 退出码 1 → 报告全部 FAIL 项，不进入阶段二 |
| 阶段二 | 读 .venus/config.yaml 的 runtime_dir（默认 vendor/auto-package-svn）→ 调 auto-package.sh -v 监控输出 | 路径不存在→报错提示配置；打包退出码非 0→解析 stderr 暂停报告 |
| 阶段三 | 跑 verify-package.sh --strict 以 SVN 变更清单核对产出 | 有差异 FAIL → 报告缺失/应删未删/多余，不进阶段四 |
| 阶段四 | 扫描产出 + 读 readme.txt 反查提案 + 归集 SQL/配置 | 反查失败静默降级，仅归集产出文件信息，仍输出升级文档 |

```pseudocode
// 来源: design.md D11 + 阶段四反查降级逻辑
FUNCTION 阶段四归集(产出目录, 版本号列表)
    提案集合 = {}
    FOR EACH 版本 IN 版本号列表
        change名 = 提取change名(读readme.txt(版本))
        IF change名 非空 AND openspec/changes/[change名] 存在 THEN
            提案集合[change名].加入(版本)
        END IF
    END FOR
    IF 提案集合 为空 THEN
        升级文档.头部注明("未关联到 OpenSpec 提案")
        仅归集产出文件 SQL 与配置
    ELSE
        按提案集合去重分组，归集提案来源 + 产出文件来源
    END IF
    输出 升级文档.md 到 产出目录
END FUNCTION
```

## 七、影响分析

### 模块影响
- **技能体系模块**（src/core/templates/）：新增 release-package.ts 模板 + registry 注册，经 getSkillTemplates 自动传播到 init/generate/list/show/validate/update 全消费者
- **vendor 模块**（vendor/auto-package-svn/）：新建目录，备份 auto-package 运行时（含 2.4MB ecj jar 二进制），git-tracked
- **项目配置**（.venus/config.yaml）：workflows 列表新增 release-package + 新增可选字段 auto_package.runtime_dir
- **测试模块**（test/）：5 个测试文件技能数量计数断言 23→24
- **快照与安装产物**（skills/、.claude/skills/）：新增 venus_release_package/ 目录（SKILL.md + 校验脚本 + 参考文档，不含打包脚本本体）

### 客户影响
- 无外部客户影响（本项目为技能生成 CLI，新增技能不影响既有 CLI 行为）
- 新技能不入默认集，现有项目 venus init 行为不变（除非显式勾选）
- vendor/auto-package-svn/ 含 2.4MB 二进制 jar，git 仓库体积增加（一次性，可接受）

### 调度影响
- 无调度任务影响

### 无影响项
- 不改 SKILL_TYPES（不新增类型）
- 不改 DEFAULT_WORKFLOWS / DEPS
- 不改 auto-package.sh 本体逻辑（仅备份）
- 不改 venus init/CLI 二进制资产部署机制（路径可配置已解决）
- 向后兼容（新增技能 opt-in 安装，runtime_dir 可选字段缺省用默认）
