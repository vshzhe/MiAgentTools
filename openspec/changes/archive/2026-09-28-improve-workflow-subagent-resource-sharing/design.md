## Context

本仓库是 AI 技能生成与管理 CLI：`src/core/templates/workflows/*.ts` 为模板工厂（技能 SKILL.md + 指令 .md 模板对），经 `registry.ts` 注册后由 `pnpm build && pnpm generate:skills` 快照分发到 `skills/`。**模板正文是唯一可编辑真源**；`skills/` 是生成产物。

改造对象为五个模板中的**派发层 prompt 文本**（非运行时代码）：

| 模板 | 派发形态 | 现状冗余（证据） |
| :--- | :--- | :--- |
| `spec-apply.ts`（494 行） | 批次调度，每派发单元一子代理 | 调度指令 MUST 内联「全量任务细节 + 制品列表 + 规范摘要」（`:170-176`）；跨批零共享；回执未禁粘贴代码（`:176`） |
| `tr-impl-auto-workflow.ts`（680 行） | ①1.2.1.5 多项目扫描 ②Phase 4 继承 apply 调度 | ①每项目一子代理、顺序派发（`:312-315`）②继承声明未覆盖共享协议（`:536`） |
| `tr-impl-workflow.ts`（2286 行） | 1.2.1.5 多项目扫描（与 auto-workflow 同构，双处正文） | 每项目一子代理、明文 "sequentially"（`:363-383` skill 版 / `:1896-1916` command 版） |

**命令派生双轨制**（`tr-workflow-suite-skills` 能力记忆三次记录的陷阱）：`spec-*.ts` 的 command 版由 `deriveCommandContent()` 自动派生（改 skill 正文即同步）；`tr-*.ts` 的 command 版为**手写压缩正文**，须手工双处同步。

**规格缺口**：`spec-workflow-skills/spec.md:157` 的 spec-apply 需求只覆盖「呈现统一批次计划」，派发单元 / 子代理派发 / 并发上限 / 调度指令内容 / 临时工作区协议**全部无规格覆盖**；`tr-workflow-suite-skills/spec.md:99` 只表述「执行 apply 的 Step 6+ 批次调度行为」。本变更一并补齐。

**流程基准**：探索阶段产出的 **4 条链路 / 41 节点**功能流程图（经 1.5.5 流程最终确认门确认；1.6 一致性裁决 D17/D18 后回改补建流程 4 并**重新确认**），tasks.md 逐任务标注 `[N<id>]`，验证时节点覆盖度以 41 为分母。回改严格遵循「不在任务清单静默补节点」的 guardrail。

## Goals / Non-Goals

**Goals**:

- 让每个子代理的上下文消耗与派发单元数**解耦**：协调者一次性产出共享上下文包，子代理只读包 + 本单元任务清单（`[N5]`/`[N6]`/`[N8]`）
- 建立跨批次信息共享（产出登记表），消除「下一批只能重扫代码」（`[N10]`）
- 压缩协调者侧上下文（回执最小化，禁止粘贴代码正文）（`[N8]`/`[N10]`）
- 消除多项目扫描的 N 次子代理冷启动（单子代理串行扫描）（`[N20]`）
- 消除 debug 调试循环内的重复 CodeGraph 查询（探查摘要先读复用 + 增量写入）（`[N23]`–`[N30]`/`[N35]`）
- 消除 auto-migration 的规范要点重复内联（改写入包）（D18）
- 补齐派发协议的主规格缺口，使实现与规格对齐

**Non-Goals**:

- **不降低实现质量**：不减少派发单元数、不合并任务、不降低并发上限默认值 3、不放宽编译/测试关卡
- **不新增子代理派发能力**：`venus_tr_impl_debug` 保持单代理流程（仅共享探查缓存）
- **不改运行时代码**：`derive-command.ts` / `registry.ts` / `profiles.ts` / `allowedTools` / CLI 命令均不动
- **不改共享内联源**：`prompt-gate.ts` / `flowchart-gate.ts`（爆炸半径大且与本需求无关）
- **不同步 propose / bulk-archive 的派发**（派发粒度不同，记为已知落差）
- **不做实测 token 计量**（无法在 vitest 复现，改以可断言的结构指标验收）

## Decisions

### D1: 单一定义源——共享资源协议规范地定义在 `spec-apply`

- **选择**: 协议规范文本只写入 `src/core/templates/workflows/spec-apply.ts`（唯一源）；其余技能**通过既有的「继承 apply 协议」表述**获得行为，仅在措辞上**显式声明继承关系**，不复制协议文本。
- **理由**: `spec-apply` 是 auto-workflow / auto-migration / workflow / genfull 的共享行为源；复制粘贴到 N 个技能会引入 N−1 个漂移面（本能力历史上「双模板漂移」实录 4 处，含 1 处防护语句缺口）。
- **备选**: ①逐技能全量复制（否决：漂移面爆炸）；②抽 `context-pack.ts` 共享内联模块（否决：用户裁决为「单一源 + 显式声明继承」；且 apply 层的包协议与 prompt-gate 这类跨技能共享块性质不同——它只在 apply 派发链路上生效，不需要内联进 5 个技能）。

### D2: 上下文包一次性产出 + 逐批追加登记表

- **选择**: 设计确认后、首次派发前一次性产出 `context-pack.md`（六节）；此后每批完成**只追加**登记表行，不重产整包。
- **理由**: 包的「契约 / 规范要点 / Codebase 摘要」三节是流程内不变量，重产等于重复蒸馏；「已产出」节是唯一随时间变化的部分，追加即足。
- **备选**: ①每批前重产全包（否决：重复蒸馏，token 成本回升）；②包冻结 + 独立 `ledger.md`（否决：子代理必读文件数从 1 升为 2，与「唯一必读制品」目标相悖）。

### D3: 包内容六节

- **选择**: `## 变更摘要`（proposal Why/What 蒸馏）/ `## 契约`（接口签名 · 数据结构 · 表字段，由 specs + design 蒸馏）/ `## 规范要点`（`ai-coding.md` 蒸馏一次）/ `## 文件归属表`（单元 → 允许改动文件）/ `## Codebase 摘要`（协调者预扫描结论）/ `## 已产出（跨单元可见）`。
- **理由**: 前三节覆盖子代理原本要从 proposal/specs/design 读的全部信息；第四节把既有 Step 6.3 的跨单元重叠检查结论**固化为可读约束**；第五节消除子代理自查代码库的需要；第六节承载跨批共享。
- **备选**: 精简为三节（变更摘要 / 规范要点 / 已产出）——否决：契约与文件归属表正是子代理最常重读的内容，砍掉则重读无法避免。

### D4: 调度指令瘦身——移出内联规范摘要，保留内联任务细节

- **选择**: Step 6.5 必含清单改为「包路径 + 本单元任务清单（含全量细节与 Spec Ref）+ 回执格式 + 禁止项」；`ai-coding.md` 规范摘要**移出**（改引用包 `## 规范要点`）。**任务细节保持在指令内联**，使子代理无需读 tasks.md。
- **理由**: 规范摘要在 N 个单元间**完全相同**（纯冗余），而任务细节**单元间不同**（内联避免子代理读 tasks.md 的固定开销）。这是「什么该共享、什么该内联」的分界：**跨单元不变量共享，单元变量内联**。
- **备选**: 任务细节也改引用 tasks.md——否决：子代理需读整份 tasks.md（含其他单元的任务）才能定位自己的部分，净增消耗。

### D5: 禁止项的可执行边界——允许查缺 + 强制缺口回执

- **选择**: 子代理 MUST NOT 重读 proposal/specs/design、MUST NOT 重跑包已覆盖的查询；MAY 查包未覆盖内容，但回执 MUST 附**包缺口回执**，协调者据此回填包。
- **理由**: 严格的「仅允许查 gap 标注项」会因包蒸馏不完美而频繁暂停（防护反成形式）；无回执机制的纯指导语则使「是否真的未重扫」不可度量。允许查缺 + 强制回报是**可执行且不阻断**的折中。
- **备选**: ①仅允许查 gap 标注项（否决：频繁暂停）；②纯指导性禁止语（否决：验收不可断言）。

### D6: 回执格式固定四列

- **选择**: `<任务 id> | <状态> | <产出文件> | <公开签名>`，MUST NOT 粘贴代码正文；失败任务额外含失败原因摘要。
- **理由**: 协调者侧上下文是本次优化的另一半——回执粘贴代码会把省下的进口 token 从出口还回去。保留失败原因摘要是因为「不粘贴代码」≠「不报错误」。
- **备选**: 不约束回执格式（现状）——否决：这是当前协调者上下文膨胀的直接来源。

### D7: 共享指令前缀固定顺序

- **选择**: 指令结构固定为「共享前缀（包路径 / 规范要点引用 / 回执格式 / 禁止项）→ 单元差异（任务清单）」。
- **理由**: 同流程内变更名恒定 → 包路径恒定 → 前缀字节一致，为提供方前缀缓存提供命中条件；同时使指令结构可预测、便于审查。
- **备选**: 不约定顺序（现状）——否决：单元无关段与差异段混排，无缓存友好性且审查成本高。
- **注**: 缓存收益依赖运行时能力，本变更只**创造条件**（前缀一致），不承诺命中；故验收只断言结构顺序，不量化缓存收益。

### D8: multi-workflow 继承显式化

- **选择**: `tr-impl-auto-workflow.ts` §4.1 新增继承声明句，显式列出四载体并声明 MUST NOT 另立派发指令格式。
- **理由**: 现状正文只说「following the venus_spec_apply skill's Step 6+ batch scheduling behavior」（`:536`），改造后语义不明——不显式声明则实现者可能照旧内联规范摘要。
- **备选**: 依赖既有「following …」表述自动覆盖——否决：共享资源协议超出「批次调度行为」的字面范围，须显式补齐。

### D9: 多项目扫描单代理化（auto-workflow + workflow 同构同步）

- **选择**: 1.2.1.5 由「每项目一子代理」改为「**单子代理内串行扫描全部待查项目**」；降级保持**项目粒度**（某项目失败仅该项目降级 Glob/Grep）。
- **理由**: 原实现是**顺序**派发（`tr-impl-workflow.ts:371` 明文 "sequentially"），**无并行收益却有 N 次冷启动**——合并为 1 次是严格改进（token 降、耗时持平）。两处同构必须同步，否则立即漂移。
- **备选**: ①改为**并行**派发（否决：与「降 token」目标相悖，且并行子代理仍需 N 次冷启动）；②仅改 auto-workflow（否决：一致性裁决 D17 已定同步）。

### D10: debug 探查摘要——流程级工作区载体

- **选择**: 新增 `.openspec-tmp/debug-<keyword>/investigation-digest.md`；Phase 2 起始先读、仅增量查询、增量写入；调试循环回边先读；Phase 7 收尾清理（含非缺陷/中途退出路径）。
- **理由**: ①**必须落盘**——长循环（≥5 轮）遇上下文压缩后会话内摘要丢失，复用失效；②落**流程级**工作区而非变更目录——Phase 2 时变更尚未确定（Phase 3 才判关联），且 `attachments/` 是交付物目录不宜放缓存；③与 `spec-apply` 的 `.openspec-tmp/` **同级同款**（入 `.gitignore`、流程结束清理），复用既有约定而非新造。
- **备选**: ①仅会话内诊断记录复用（否决：压缩后失效）；②落变更目录 `attachments/`（否决：污染交付物 + Phase 2 时变更未定）。
- **划界**: 摘要**是流程内缓存**，MUST NOT 替代诊断记录或 Phase 6 对 `exploration.md` 的持久化；清理摘要不得影响交付物。

### D11: auto-migration 规范要点改写入包

- **选择**: Phase 3 的「每子代理指令内联注入目标项目规范要点」改为「写入包的 `## 规范要点` 节（附加来源合并）」，BINDING 约束地位不变。
- **理由**: 内联注入正是本次要消除的同类冗余；不改则子代理同时收到包内要点与内联注入**两份**。
- **备选**: 保持内联并存（否决：一致性裁决 D18 已定改为写入包）。

### D12: 规格缺口一并补齐 + 三 capability 拆分

- **选择**: 派发协议与共享资源协议作为 **ADDED Requirement** 写入 `spec-workflow-skills`（补齐缺口）；auto-workflow 继承 / 多项目扫描单代理化 / debug 探查摘要写入 `tr-workflow-suite-skills`；auto-migration 规范要点写入 `tr-migration-skills`。
- **理由**: 改造的机制当前**无任何主规格覆盖**，只写 delta 而不补规格会使实现继续游离于规格之外。三 capability 的划分依据是**既有能力归属**（auto-migration 的主规格在 `tr-migration-skills`，不在 `tr-workflow-suite-skills`）。
- **备选**: 全部挤进一个 capability——否决：与既有能力划分冲突，归档合并会越界。

### D13: 包机制 fail-safe 降级

- **选择**: 工作区不可写 / 包产出失败 / 项目无 `ai-coding.md` → 退化为既有内联注入 + WARN，**绝不阻断实现**；工作区不可写时先回退系统临时目录（沿用 `spec-apply.ts:141` 既有回退）。
- **理由**: 对照 `derive-command.ts` 的 fail-safe 裁剪哲学——机制失效只会让指令更长，**不会缺失防护**。派发层增强绝不应成为实现流程的单点故障。
- **备选**: 包产出失败即暂停——否决：把「省 token 的优化」变成「阻塞流程的风险」，得不偿失。

### D14: auto-mode 不豁免 / 单任务批次不产出包

- **选择**: `auto-mode=true` 只跳过 Step 5.5 设计确认门，包机制照常生效；批次含 <2 派发单元时不产出包（协调者直接实现）。
- **理由**: auto 语义的豁免面应严格限定为「需人确认的门」；单任务批次无子代理则无共享需求，产出包是纯浪费。
- **备选**: auto-mode 全豁免（否决：全自动管线恰是长流程、最受益于共享协议）；单任务批次也产出包（否决：无谓产物）。

### D15: 验收以可断言的结构指标为准（A1–A8）

- **选择**: A1 包六节 + 路径 + 产出/追加规则 · A2 Step 6.5 不再内联规范摘要 · A3 三项禁止句 + 缺口回执字段 · A4 指令固定顺序 · A5 继承声明句 + 单子代理串行扫描（**`tr-impl-auto-workflow` 与 `tr-impl-workflow` 双技能双处**）· A6 debug 探查摘要段（双处）· A7 既有测试全绿 · **A8 auto-migration 规范要点写入包断句 + MUST NOT 内联 + 退化分支（双处）**。落地为 `test/` 新增断言 + 全量 vitest 回归。
- **理由**: 真实 token 计量无法在 vitest 中复现；结构指标可断言、可回归、可防止后续漂移（与本仓库既有断言风格一致——`templates.test.ts` 已用字面子串断言，如 `'🟠根因'` / `not.toContain('| 异常路径 |')`）。
- **备选**: ①追加实测 token 比对（否决：不可在 CI 复现，人工执行不进断言）；②只保既有测试（否决：本次核心是 prompt 文本改造，无新增断言则回归无防线）。

## Risks / Trade-offs

| 风险 | 缓解 |
| :--- | :--- |
| 包的蒸馏质量不足 → 子代理频繁走缺口回执，协调者回填开销抵消收益 | 六节覆盖子代理原本必读的全部信息源；缺口回执本身是**度量信号**（缺口率高说明蒸馏需改进）；回填失败仅 WARN 不阻断 |
| 「禁止重读」被误解为「可跳过制品」→ 合同字段凭包猜测（反幻觉失效） | 规格明文：**包是蒸馏视图而非替代品**，缺项时 MUST 补查制品本身，MUST NOT 凭包猜测；`## 契约` 节的字段以制品原文为准 |
| 共享指令前缀的缓存收益依赖运行时能力，可能为 0 | 本变更只**创造条件**不承诺收益；验收只断言结构顺序，不量化缓存；无缓存时仍因指令内冗余消除而净收益 |
| 单子代理串行扫多项目 → 某项目扫描慢时整体串行变长 | 原实现本就是顺序派发，**耗时不增**；降级保持项目粒度，一个项目失败不阻塞其他 |
| debug 探查摘要与诊断记录职责混淆 → 摘要被当作交付物持久化 | 规格明文划界：摘要清理 MUST NOT 影响交付物；诊断记录与 Phase 6 持久化照常执行 |
| 包 `## Codebase 摘要` 过时（协调者预扫描后代码被前序单元改动） | `## 已产出` 节随批追加，后序单元能从登记表获知前序改动；摘要定位为**起点**而非终态 |
| 双轨制陷阱：4 个 tr 技能的 command 版为手写压缩正文，漏同步 → 指令版行为与 skill 版不一致 | 规格与 tasks 逐技能标注「双处同步」；`skills-parity.test.ts` 覆盖 SKILL.md 快照（不含 command 文件），故 command 同步靠 tasks 检查项与 A5/A6 双处断言 |
| `spec-apply` 新增段落默认进入 command 版（derive 的 fail-safe 语义）→ command 版体积增长 | fail-safe 是**有意设计**（漏标只会更长、不会缺失防护）；逐段判定 `<!-- CMD:SKIP -->` 标记列入 tasks，并在实现期核对 command 版可读性 |
| `test/templates.test.ts` 断言 debug 正文不得含 `\| 异常路径 \|` 列头 | 新增探查摘要段避开该列头字样；实现后跑全量 vitest 核对 |
| 新增 7 个术语与既有术语冲突 | 探索阶段已在探索文件术语表定义并给出 `_Avoid_` 对照；归档时合并进 `CONTEXT.md` 前再次核对 |
| **P2 已披露（深度复查发现，不补规格）**：包产出失败后**是否重试一次**未规定 | 退化路径（D13）已保证不阻断；是否重试为协调者判断余量，规格不强制。若实现期认为必要，在模板正文中补「重试一次后仍失败即退化」即可，无需改规格 |
| **P2 已披露**：包 `## 契约` 含表字段 / 接口签名，落盘于 `.openspec-tmp/`（已入 `.gitignore`） | 内容全部蒸馏自本仓制品，无制品外信息；实现期在模板正文补一句「包 MUST NOT 写入凭据等制品之外的敏感信息」即可 |
| **P2 已披露**：单子代理扫描多项目时 `projectPath` 的逐项目切换用法 | 规格已要求「使用 `projectPath` 参数」；实现期在正文写明「对每个项目分别以其路径调用 codegraph 工具」使语义更明确 |
